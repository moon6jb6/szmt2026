## 4. 给 Lead 的结构观察（都在树里可核对）

### 4.1 没有「多路线」，只有「选项汇流」

337 条边里，**没有任何一个场景被 2 个以上不同场景指入**（多父合并点 = 0）。每个场景的 2—4 个选项都指向同一个后继场景，所以：

- 语义上的分支在**结果文本 / 记忆账本 gain / flags**，不在场景序列；
- 图上能看到的「汇流」是**入边 ≥ 2**（114 处，节点角标 `⇥N`），即「一个场景的多个选项汇入下一个场景」；
- 真正的路线分歧只在**尾声**：9 个结局。

这不是脚本漏抓——`choices[].next` 328 条全部读过，`Scene` 顶层没有 `next`，`continueTo` 0 处使用。若未来出现「选项指向不同场景」，脚本会自动把多父合并点标成紫色并在自检里报数。

### 4.2 25 个读者页是设计如此，不是断链

「后来」15 篇 + 「人物志」10 篇由 App 的清单页直接渲染（`App.tsx` 的 `screen === 'later' / 'people'`），不进 engine 状态机、不挂 `choices`。这正是 `check-volumes.mjs` 报的 25 个「未被指向」。树里单独成节、卡片虚线边框、并标注 menu-only。

### 4.3 载体稀缺度不均：照片结局最窄

- **照片**：全作只有 2 个场景（`night4`「把名字交出去」、`v3-18`「相机」）、3 个选项能加（上限 1）→ 想开「照片」结局与合成「遗物」（家书+照片），必须先拿到照片；
- **旗**：20 个场景 / 25 个选项（上限 1）→「旗」结局与合成「口耳」（旗+口信）次窄；
- **名册 / 口述**：91 / 102 个场景可得 → 主结局几乎必开，合成「档案」最容易凑齐。

### 4.4 `gain` 有 2 点但 `LEDGER_CAP` 封 1（引擎行为，非树的错）

`旗 / 照片 / 口信` 的上限是 1，但个别选项 `gain` 写 2（单项最大 = 2）。`engine.applyGain` 会 `clampLedger` 到 1，即那 1 点会被丢掉。树里照源码显示 `gain: 2`，引擎实际生效按 1——如果要做数值向的复核，这是唯一需要人眼确认的小口径。

### 4.5 `flags` 目前只写不读

全仓 `state.flags` 只有 `engine.ts:75` 一处写入合并，没有任何读取处（`grep -r "\.flags" src` 仅此一条）。也就是说 318 个选项带的 flags（`carry_body`、`lock`、`copy` …）目前是**纯记录**，不参与分支也不参与结局判定。树里保留并逐条展示（`⚑` 标记 + 侧栏），将来接上读取逻辑时可直接核对。

## 6. 如何打开 / 怎么用

**打开（不需要起服务器）**：双击 `docs/report/剧情树.html`，或在浏览器地址栏打开该文件的 `file://` 路径。单文件、离线、无 CDN。

- 默认「按卷折叠」：7 个小节（序卷 / 卷一 / 四行五夜 / 孤军营 / 尾声 / 后来 / 人物志），点标题展开该卷。
- 节点上：标题 + `id` + 段落数 + 天气/地点 + `N 选`（选项数）+ `⇥N`（入边数）；金色 = 主结局，红色 = 合成结局，青边 = 跨章接缝点，虚线 = menu-only 读者页。
- 每条边 = 场景右侧的一个小标签（选项短标签，截断到 10 字；完整文案在侧栏与 `title` 提示里）。
- 点**节点**或**选项标签** → 右侧栏：章节/时间/地点/天气/段落数/出处卡数/入边数 + **完整选项表**（选项、提示、去向、gain、flags）+ 前后节点（可点击跳转）。
- 顶部搜索框按标题/id/章节/地点过滤，命中的节自动展开并高亮，右侧显示「匹配 N / 149」。
- 每节画布支持**滚轮缩放 + 拖拽平移**，还有 `＋ / − / 适应 / 1:1` 按钮。
- URL 参数：`?open=night`、`?open=vol0,vol1`、`?open=all` 指定默认展开；`?flat=1` 为截图模式（整幅铺开、不裁切）。

## 7. 方法与约束（怎么做到「不手抄、不编造」）

1. **解析方式**：用本仓已装的 `rolldown`（vite 8 的打包器，devDependency 已存在）把 `chapter1.ts`、`volume0.ts`–`volume5.ts`、`endings.ts`、`registry.ts` 分别打成 ESM 落到系统临时目录（`%TEMP%/story-tree-bundle/`），再 `import` 读真实导出值。**拿到的是 TypeScript 求值后的对象**，不是正则抓字面量；场景字段、`gain`、`flags`、`ending` 全部原样。

4. **结局**从 `endings.ts` 的 `ENDINGS` / `COMPOSITE_ORDER` / `COMPOSITE_REQUIRES` 读，不硬编码 id 映射（`ending_names` 这种特例也是从 `buildEpilogue` 的返回值里读到的）。

   - 只新增/改动 5 类文件：`tools/story-tree.mjs` + 4 个 `docs/report/*`（本报告为第 5 个）；
