# 参赛打包说明（`tools/package.mjs`）

> 适用：《把名字留下来》2026 年第十四届全国大学生数字媒体科技作品及创意竞赛参赛包。
> 一句话：**改完东西 → 跑一条命令 → 得到的 ZIP 就是提交包**，包内结构、匿名化、数字对账由脚本自动核对，结果写进 `docs/report/2026-10-22-package-manifest.json`。
> 最后更新：2026-10-21（首版试打包已跑通，输出在 `trash/_package-test-2026-10-22/`，未提交）

## 1. 一条命令

```powershell
# 在项目根目录  frontend/2026数字媒体/  执行
node tools/package.mjs --name "把名字留下来_<作品编号>" --out "D:\提交\把名字留下来_<作品编号>.zip"
```

没报名、只想先体检（不生成 ZIP，只写 manifest）：

```powershell
node tools/package.mjs --dry-run
```

默认输出（不填 `--out` 时）：

```powershell
node tools/package.mjs
# → ../../trash/_package-test-2026-10-22/把名字留下来_待填编号.zip
#   默认名是占位名，只用于试打包，不能直接提交
```

**前置条件**：`node --version` ≥ 18（本机 v24）；`dist/` 是最新 `npm run build` 产物。脚本不自己 build，但会核对 `dist` 是否晚于 `src/`、`public/` 的改动 —— 落后就判阻断（`checks.dist.staleness`），提示先构建再打包。

### 参数

| 参数 | 说明 |
|---|---|
| `--name "作品名称_作品编号"` | ZIP 内根目录名 + ZIP 文件名。默认 `把名字留下来_待填编号`（占位） |
| `--out <zip 路径>` | 输出位置；给目录则拼 `<目录>/<name>.zip`，扩展名非 `.zip` 自动补 |
| `--dry-run` | 只体检 + 写 manifest，不建暂存树、不写 ZIP |
| `--keywords <json>` | 换敏感词表（见 §7） |
| `--manifest <json>` | manifest 输出路径，默认 `docs/report/2026-10-22-package-manifest.json` |
| `--note "<文本>"` | 本次运行备注，写进 manifest（试打包/正式包靠它区分） |
| `--no-staging` | 打包后删掉本次自建的暂存树（默认保留，方便人工核对） |
| `--allow-out-in-repo` | 允许 ZIP 落在项目仓库内（默认禁止，免得把包提交进 git） |
| `--quiet` / `--help` | 只输出结论行 / 看帮助 |

退出码：

| 码 | 含义 | 该做什么 |
|---|---|---|
| `0` | 打包成功且**无阻断项**（`readiness.submissionReady: true`） | 可以交 |
| `2` | 包已生成 / 体检已跑，但仍有阻断项（缺视频、缺线下材料、编号是占位、PDF 过期、匿名化不过） | 看 `readiness.blockers` 逐条补，补完重跑 |
| `1` | 失败：缺必交文件、ZIP 写入或回读校验不过、参数错 | **这个包不存在或不可信，不要上传** |

## 2. 报名后怎么改编号

作品编号报名后由系统生成，**编号是名字的一部分**，必须重打包一次，不要手动改 ZIP 里的文件夹名（会丢 UTF-8 标志位、也会让 manifest 对不上）。

```powershell
# ① 拿到编号后，用真实名字重跑（--name 同时决定 ZIP 内根目录名和 ZIP 文件名）
node tools/package.mjs --name "把名字留下来_A1B2C3" --out "D:\提交\把名字留下来_A1B2C3.zip"

# ② 看结论：manifest 里 "nameIsPlaceholder" 应变成 false
#    "readiness.submissionReady": true 才是真正可交
```

要改的地方只有一处：`--name`。`tools/package.mjs` 里没有写死作品名或编号。

> 占位名 `把名字留下来_待填编号` 会被脚本标成 `nameIsPlaceholder: true` 并计入阻断项。
> 目录名/文件名请用「作品名称_作品编号」全角/半角一致，不要带空格、斜杠、`: * ? " < > |`。

│  ├─ 美术报告/                ← image-manifest.json / scene-map.json / image-qa-report.md / spot-check.md / visual-bible.md / README.md

## 4. 哪些是占位 / 待补

| 位置 | 现状 | 补法 |
|---|---|---|
| `02_作品展示视频/` | **空**，只有占位说明 | 录评审视频（≤5 分钟、1080P、MP4）→ 放进该目录 → 删掉「占位说明.txt」→ 重跑打包 |
| `报名与承诺书（线下办理）/` | **空**，只有占位说明 | 报名系统填完 + 承诺书盖章扫描 → 放进该目录 → 删占位说明 → 重跑打包 |
| `01_作品及成果文件/` | 已齐（dist 550 文件，以 manifest `totals.distFiles` 为准） | 若改过 `src/` 或往 `public/` 加了素材（例如 3D 模型 `*.glb`），**先 `npm run build` 再打包**；脚本会判 dist 过期并阻断 |
| 文档 PDF | 已齐 5 份 | 但只要 `.md` 比 `.pdf` 新，脚本就判 `STALE` 并计入阻断项 —— 改了文档必须重出 PDF |

**「占位说明.txt」是给评委看的，不是给我们看的。** 里面只写三件事：这里该放什么、现在为什么空、怎么补。不含任何伪造内容或占位素材。

## 5. 打包器自动做的 7 项检查

| 检查 | 判定 | 不过会怎样 |
|---|---|---|
| `checks.dist` | `dist/` 存在、`index.html` + `assets` + `art` + `bg` + `audio` 都在、`index.html` 没有根绝对路径（`src="/assets/…"`，R1 回归） | 写进 `warnings`，并计入 `readiness.blockers`（阻断提交） |
| `checks.dist.staleness` | `dist/index.html` 的构建时间必须晚于 `src/`、`public/` 里所有会被打进包的文件（`.ts/.tsx/.css/.glb/.jpg/.ogg…`） | 判「dist 过期」并阻断：先 `npm run build` 再打包 |
| `checks.dist.metrics` | `dist` 实测文件数/字节数/art/bg/audio/javascript/css 与 `2026-10-22-afternoon-metrics.json` **逐项对账** | 列出差异项并阻断（数字只认 metrics，脚本不写死） |
| `checks.pdfFreshness` | 5 份 PDF 的 mtime 必须 ≥ 对应 `.md` 的 mtime | 判 `STALE`，计入阻断项，提示重出 PDF |
| `checks.screenshots` | `screenshots/` 恰好 10 张 `*.png` | 数量不符记 `warnings` |
| `anonymity` | 敏感词扫描（文件名 + 文本正文 + PDF Info 字典） | `block` 命中 → `FAIL`，必须清掉 |
| ZIP 回读校验 | 自读中央目录逐文件比大小 + 校验 UTF-8 标志位 + bsdtar 条目数交叉核对 + **Windows .NET `ZipFile` 读出根目录名** | 任一不符 → 退出码 1 |

`readiness.blockers` 是「能不能交」的唯一结论：视频空、报名承诺书空、名字还是占位、PDF 过期、匿名化 FAIL —— 这五类会一直在，直到真的补齐。

## 7. 匿名化检查与敏感词表

**结论口径**：`block` 命中即 `FAIL`；只有 `caution` 命中记 `REVIEW`（需人工看上下文）；都没有则 `PASS`。

扫描范围（诚实披露，见 manifest `anonymity.limitations`）：

- **扫正文**：包内 `.md / .json / .txt / .html`（21 个文件、约 0.8 MB、1.2 万行）
- **只扫文件名**：`01/` 下的 `assets/*.js`、`*.css`、496 张 `*.jpg`、28 条 `*.ogg` 等二进制/构建产物
- **PDF**：解析 Info 字典（`Title / Author / Subject / Keywords / Creator / Producer / 日期`）并检查明文；**PDF 正文流是压缩的，没有逐页提取文字**
- **没做**：截图 OCR、像素级人像检测、EXIF 剔除

本项目当前结论（2026-10-21 试打包）：`PASS`，`block=0`、`caution=0`、声明豁免 1 条。
那 1 条是 `FINAL-fact-audit.md:56` 的「凶手姓名未列」—— 指叙事角色，不是参赛者，已写进 `anonymity.exempted[]` 连同理由。**豁免必须留痕**，不要在代码里悄悄跳过。

为什么 `assets/*.js` 不做正文扫描：这作的名字就叫《把名字留下来》，11.3 万字正文里「姓名/名字」是主题词，扫了全是剧情用词，只会淹没真命中。

## 8. 常见问题

**Q：为什么不用系统 `tar` 或 `Compress-Archive` 打包？**
A：系统 `tar`（bsdtar）在中文 Windows 上把文件名写成 **GBK 且不置 UTF-8 标志位**（实测：`把名字留下来` 的字节为 `B0 D1 C3 FB…`，`utf8Flag=false`）。评委用英文系统、macOS 或某些解压软件打开就是乱码。所以脚本用 Node 自带 `zlib` 自己写 ZIP：文件名统一 UTF-8 + 置 EFS 标志位（0x800），并在打包后用 **Windows 自带 .NET `ZipFile`** 回读一遍根目录名做实证。实测：`Expand-Archive` 解出的 573 个文件与打包前的暂存树逐字节相同；抽样对源文件（5 份 PDF、`index.html`、音效、插画、背景图）的 sha256 亦全等。

**Q：ZIP 比原文件小得不多（约 93%）？**
A：496 张 JPG、28 条 OGG、PDF 已是压缩格式，deflate 压不动；真正能压的 `.md/.json/.js` 只占一小部分。29 MiB 量级，离 10 GiB 上限很远。

**Q：manifest 里的 `archive.path` 指向 `trash/`，能交吗？**
A：那说明最后一次是**试打包**。正式提交用 `--out` 指到仓库外（例如 `D:\提交\…`）再跑一次，manifest 会更新成正式路径与新的 sha256。`readiness` 里也会写着是不是占位名。

**Q：`STALE` 但我不想重出 PDF 行不行？**
A：不行。`STALE` 意味着 `.md` 改过、PDF 还是旧数字；评审只看到 PDF，「文档数字与实测不一致」正是本项目最容易被扣分的点（见 `成果状态.md` 第四部分）。

**Q：脚本会不会删我的文件？**
A：不会。它只做三件写操作：① 在 `--out` 同级目录建 `_staging/<name>__<时间戳>/` 暂存树并复制文件；② 写 ZIP；③ 写 manifest。源目录一个字节都不动。`--no-staging` 只会删它自己在本次运行中新建的那个暂存目录。

**Q：`--out` 目录下老出现 `_staging/`，越堆越大？**
A：每运行一次都会新建一份 `<name>__<时间戳>/` 暂存树（约与包同体积），保留是为了人工核对包内到底装了什么。反复试打包后可以手动清掉 `_staging/` 下旧的时间戳目录，或用 `--no-staging`（只在本次 ZIP 回读校验通过后才删自己刚建的那份）。

**Q：终端中文显示乱码？**
A：先 `chcp 65001`，或直接用 Windows Terminal。这是控制台代码页问题，不影响包里的文件名（包内是 UTF-8 + EFS 标志位）。

**Q：manifest 里的数字和 `提交清单.md` 不一致？**
A：以 manifest（实测）和 `docs/report/2026-10-22-afternoon-metrics.json`（唯一数字源）为准。`提交清单.md` 里若有旧数，属于待修文档，不是打包器的问题。

## 9. 边界与约定

- 只写 `tools/package.mjs`、`docs/deliverables/打包说明.md`、`docs/report/2026-10-22-package-manifest.json`；不碰 `src/`、不动已有交付件、不删任何文件。
- 缺**必交源文件**就报缺项（`missing[]`）并以退出码 `1` 结束；可选/线下缺项用占位说明 + 退出码 `2`。**不伪造内容**，占位说明只描述缺口与补法。
- 数字一律来自 `dist` 实测或 metrics JSON，脚本内不写死会漂移的数字；对账不过会明确列出差异项。
- 包内目录结构、文件名与 `docs/deliverables/提交清单.md` §二一致；规范若有变动，改脚本顶部 `DIR_SPEC` / `ENTRY_SPEC` 两处即可，其余逻辑不用动。
