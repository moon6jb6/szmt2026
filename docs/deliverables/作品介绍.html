﻿# 《把名字留下来：四行仓库·苏州河北岸的四百余个名字》作品介绍

一、项目定位

1.1 创作背景

四行仓库保卫战是淞沪会战的最后一战。1937 年 10 月 26 日至 11 月 1 日，88 师 524 团一营据守上海苏州河北岸的四行仓库，对外称「八百壮士」，实际四百余人。其中湖北通城籍二百人以上。

这段历史被反复讲述，但最容易被忽略的一个事实是：守军四百余人，其中两百多名通城籍士兵，最后只有八十七个名字被找回来。

1947 年，通城县参议会编《通城县抗战史料》，留下《通城县参加上海四行孤军四十九壮士姓名一览表》。此后数十年，经过 1991 年、2009 年、2013 年等多轮走访，查实姓名者八十七人，仍有百余人姓名待查。查实姓名的八十七人全部离世，最后一位周福其于 2005 年 11 月去世。

与之对照：四行仓库抗战纪念馆的英名墙，2015 年开馆时公布 323 人，到 2025 年已确认 354 人——仍然不是全部。（据新华社、人民网党史频道；详见游戏内「史料库」auto-c-02）

本作从这个「未完成的寻找」切入：把「记名字」做成玩家真正要做的动作，把「名字丢失」做成玩家要承担的结果。

1.2 目标受众与应用场景

  • 中学、高校历史与思政课堂的辅助材料（单周目 2—3 小时，可按卷拆成 4—6 个课时段）
  • 纪念馆、档案馆观众互动展项（可离线部署；人物志与「后来」可单独做展项）
  • 公众历史传播：以「名字」为入口的公共记忆项目

1.3 作品形态与时长

  • 网页端 2.5D 交互叙事，桌面优先，兼容平板与手机
  • 正文 113,048 汉字（严格口径：只统计玩家读到的正文段落），140 个场景，9 个结局（6 个主结局 + 3 个合成结局）
  • 单周目约 2—3 小时；读完全部内容（九结局 + 人物志 + 「后来」读者页 + 史料库）约 6 小时
  • 无后端、无账号，存档在本地浏览器
  • 附加可读内容：10 篇人物志（人物志清单页）、15 篇「后来」读者页、76 张史料卡史料库
  • 每一次点击都有不同的回响：六种记忆载体各自对应不同的点击粒子、选项悬停位移与强调色；换场按天气分为墨、雨、雪、灰、烟五种转场
  • 每个结局都有一段「终极画面」：名册落成册页、家书纸页翻落、旗在风里展开、照片显影、磁带里的声音画成波、石面凿出六个字——六段画面之外，三个合成结局把两种画面叠在一起

二、主要创新

创新一：把「记录」做成核心玩法，而不是把战争做游戏

玩家不是枪手，是识字的文书。核心动作只有两个：记下名字、带东西过河。

五夜，每夜只有一次过河机会，只能带走一样东西：名册页、家书、旗的图样、照片、口述、一句口信。带出去什么，什么就活下来。这个机制把历史教育里抽象的「铭记」变成了具体的取舍：你不可能全都要。

与同类题材作品的差异：不做战斗、不做杀敌计数、不做「守住/失守」的成败判定。战争是背景，选择的对象是记忆。

创新二：结局由「记忆载体」决定，而不是由胜负决定

六个主结局对应六种记忆载体：名册、家书、旗、照片、口述、口信。每个结局不排名、不分好坏，只回答「哪一种记忆被留下」。

但六种记忆组合起来，还有第三种东西。 如果玩家同时带走了两样，尾声会多出三个「合成结局」：

  • 档案（名册 + 口述）：名字和话放在同一个匣子里，纸和口述互相作证；
  • 遗物（家书 + 照片）：一件是字，一件是人，都不算史料；
  • 口耳（旗的图样 + 那句口信）：一个给眼睛，一个给耳朵。

合计 9 个结局。合成结局不是「更好的结局」，而是「记忆之间的关系被留下来了」。每个结局页还有一段「余波」，根据这一周目实际带走了几样东西给出不同的收尾句。

所有结局共享同一句结尾：「还有一百多个名字，没有人知道。」

结局不改变死亡人数，也不奖励「完美通关」。这样处理的目的，是避免把南京、731 一类的民族苦难变成可刷分的关卡——这一点在项目早期就被写成了不可违反的设计红线。

创新三：史实分层 + 游戏内史料卡

作品把内容分成两层：

  • 史实层：年代、地点、部队番号、人数、档案出处。只使用可核对的一手/权威报道，游戏内以「史料卡」形式呈现，点开即见事实与出处。
  • 表现层：天气、对话、场景细节、虚构人物的心理。允许叙事重构，但明确标注。

主角陈望生是复合型虚构角色，首次出场与「关于」页均永久标注。谢晋元等真实人物只以可查证的事实出现，不虚构其台词。

未核对的内容不进入正文。例如升旗与送旗的具体经过存在多种说法，正文只写「后来写进报纸的说法有很多种」，而不给出确定版本。

创新四：2.5D 不是贴图平移，而是父层真透视；换场不是硬切，而是墨迹幕

2.5D 主路径不引入 Three.js、GSAP 或任何动画库（GSAP 核心 + ScrollTrigger 实测 46,375 B gzip，占当时首屏 JS 的 61%，且不是 MIT 许可；Rive 需 2MB WASM，直接出局）；只有点「3D 视角」时才按需加载 three.js 与 Blender 导出的 GLB。

纵深：三个背景层放在同一个 perspective 父层里，子层用静态 translateZ 定位，指针只驱动父层 rotateX/rotateY。持续运动压测下，「每层各自 transform」是 16.9 fps，改为「父层 3D 倾斜」后 48.0 fps（2.8 倍），且纵深从平移错觉变成真透视（近层放大、远层缩小，倾斜时带梯形变形）。模糊改为烘焙在静止的内容层上——逐帧改 filter: blur() 实测会掉到 22.7 fps，而恒定 blur 几乎免费。

转场：五夜之间不再是内容跳变，而是 Canvas「墨迹幕」合拢 → 全黑 → 退开，配合推镜。换场动作发生在全黑那一帧，同时遮住了背景图解码、字体度量与重排的抖动。实测 67.2 fps、p95 17.0 ms、掉帧 4.6%；4 倍 CPU 降频仍有 64.7 fps（瓶颈在合成器不在 JS）。整套转场只增加约 1.5 KB gzip。

无障碍：prefers-reduced-motion 打开时，3D 倾斜归零、墨迹幕短路为直接换场、粒子停止，流程仍完整可玩（JS 侧分支，不依赖 CSS 的全局降级）。

这样做的结果是：首屏 JS 主包 847.26 kB（gzip 319.0 kB，主体是 113,048 字正文与 76 张史料卡数据，3D 另按需加载），dist 含背景图、插画、音频与 GLB 后约 24.59 MB，无外部字体、无外部 CDN、无动画库，断网也能跑。

创新五：11 万字不是堆出来的——分工写作 + 双轨审计的生产管线

这一版把正文从 6,000 字扩到 113,048 字（严格口径），靠的不是堆形容词，而是一条可复核的生产管线：

  • 分区写作：序卷/卷一、卷二（四行五夜）、卷三/卷四（孤军营/记忆线）、支线人物志，四个写作单元各自独立文件，互不覆盖；Lead 只做接线与集成。
  • 双轨审计：一名史实审计（逐场景对照 76 张史料卡，查真实人物台词、时间线、挂源、红线）+ 一名文学审计（五维评分：具体性/情感真实/语言干净/结构功能/意象系统，均分 ≥4.0、单项 ≥3 才通过）。
  • 可操作的质量标准：禁用清单（「仿佛/似乎/不禁/渐渐地」、三连排比、解释性旁白、第二人称叙述、大词、情绪直呼）、每段必须有具体物与具体动作、三处声音样板定调。
  • 结果：146 个叙事单元，文学 P0 红线 0、不合格 0，加权均分 4.59；史实 P0 = 0；全库 36 份审计报告（docs/audit/）、正文字数与结构可用脚本复现（tools/count-words-strict.mjs、tools/check-volumes.mjs）。

这条管线本身也是作品的一部分：它证明「红色题材 + 生成式 AI」可以不靠幻觉堆量，而靠可验证的质量门槛。

创新六：每一次点击都有回响，每一个结局都有一段「终极画面」

点击不再只是「选中一个选项」：

  • 六种记忆载体各自对应不同的点击粒子：名册是墨点与字，家书是纸片，旗是红绸与逆光，照片是白闪与银粒，口述是声波涟漪，口信是上浮的字；
  • 选项悬停也按载体给不同位移方向与强调色，键盘选择同样触发；
  • 「继续」有独立的横向墨扫；换场按天气分为墨、雨、雪、灰、烟五种转场画面；
  • 段落按奇偶错峰上浮，读长文时不是整块文字齐刷刷出现；
  • 点按的粒子参数由「场景 id + 选项 id」哈希生成，同一个选项在不同场景下的落点与数量也不同。

部分场景可以切到真 3D 视角： 四行仓库西墙、底楼、楼顶升旗、苏州河桥、1947 造册厢房共有五个真 3D 场景（西墙是 Blender 4.2.3 无头建模导出的 4,732 三角面 GLB，其余为 three.js 程序化几何），点场景页右上角「3D 视角」进入：2.5D 分层淡出，3D 背景透出，正文卡片半透明，移动鼠标改变视角（受限 yaw ±18° / pitch ±14°）。无 WebGL、开启减少动效或窗口 <700px 时不显示按钮，自动留在 2.5D。

结局不是一页文字，而是一段画面：

结局 终极画面
名册 名字像雨一样落下来，最后落成一张册页
家书 纸页翻落，最后打开一封，信纸上的折痕一条条显出来
旗 暗色地平线上，红布在风里一点点展开
照片 闪光之后影像慢慢显影，两个被圈住的人像始终看不清
口述 磁带轮转动，声音画成一条波，波上是四十九个刻度
口信 石面上一笔一笔凿出六个字，石屑落在字口里
档案 / 遗物 / 口耳 两种画面叠在一起：字雨 + 声波 / 纸页 + 显影 / 旗 + 声波涟漪

画面约 6 秒，可点击跳过；prefers-reduced-motion 打开时只显示最终帧，2 秒后进入正文。结局页可以「重看结局画面」。

3.3 视觉与声音

  • 色板：旗帜红 #A32B2B、铁锈 #7A3E2E、沙金 #C8A063、烟黑 #16130F、纸白 #EDE6D8
  • 字体：思源宋体（标题）+ 思源黑体（正文），使用系统字体回退，不请求外部字体
  • 背景图：2.5D 舞台沿用 8 张本地生成的基准背景图（1024×576）；场景插画则由同一管线扩展生成，按场景 id 映射到 140 个场景中的对应条目。
  • 图片总谱：docs/art/image-manifest.json 定义 500 条插画条目（scene 128 / moment 100 / artifact 80 / figure 60 / ui 60 / atmo 42 / ending 30），每类有固定 prompt 结构、风格前缀、negative 词表与尺寸；docs/art/visual-bible.md 规定色板、镜头语言、红线（不出现人脸、文字、现代物、旗帜图案错误）。
  • 生成与质检：本地 SDXL base 1.0（fp16）+ SDXL-Lightning 4-step LoRA，enable_model_cpu_offload；8GB 显存实测 peak_reserved=5.48 GiB（常驻方案会到 10.9 GiB，触发 Windows WDDM 共享显存抖动，已放弃）。每张图固定 seed，prompt / negative / seed / 尺寸 / 步数 / 耗时全部写入同名 JSON，可复现。
  • 逐张质检：本地 Qwen3-VL-2B 四维打分（prompt 符合度 / 时代准确性 / 画面瑕疵 / 危险元素）→ pass / retry / reject；retry 换 seed 重生成；人工每 50 张抽 10 张，重点查人脸、文字、现代建筑与「有没有叙事信息」。
  • 实际产出：500 条总谱中落盘 496 张（场景 124 / 结局 30 / 其余 342 张为 moment、artifact、figure、atmo、ui 素材），入屏图 158 条逐张过 VLM 质检，初检通过率 93.0%，重生成后 95.6% 可用；4 张不合格剔除、对应场景走渐变回退。质检台账与失败类型分布见 docs/art/image-qa-report.md。
  • 首屏体积：dist 总计约 24.59 MB（含背景图、插画与音频）；JS 主包 847.26 kB（gzip 319.0 kB，主体是 113,048 字正文与 76 张史料卡数据）、3D 切片懒加载 171.1 kB gzip、CSS 4.92 kB gzip；无外部字体、无 CDN、无动画库，断网可跑。
  • 声音设计：本作有 28 条本地生成的环境音与动作音（共 4.88 MB，OGG）：六种记忆载体各有不同的点击音、翻页/纸/笔/墨、雨（轻/重）、雪风、河水、人群低语、室内底噪、磁带嘶声、旗面拍打、脚步、火柴、收音机杂音、六种结局 drone。声音跟随场景与天气切换，同一时刻最多一条环境声 + 一条结局低音；默认静音，用户点右下角「声音」才开启，状态本地记忆。全部由本地 Stable Audio Open Small（497M，Stability AI Community License）生成，逐条记录 prompt/seed/采样率/峰值显存，可复现。

3.4 史料卡系统（可插拔，76 条）

游戏内共有 76 张史料卡：已核对 63 张（正文可用）、待核对 7 张（说法不一，只作研究记录）、待接入 6 张（登记缺哪本书的哪一章，不进入正文）。

这些卡怎么来的：书在电子书平台找不到后，我们把需要的史实拆成 56 个编号槽位（编成与人物、五夜战况、名册与口述、记忆与传播、视觉参考、红色属性、校核项），写成《史料收集字典》，交给另一个 AI 去公开来源里检索；检索结果按统一 JSON 回填后，由 tools/import-collected-sources.mjs 逐条校验并自动并入项目。此后又人工补入 20 张（四行四行储蓄会、八一三、升旗细节、孤军营精神升旗、工场等）。

  • 回填 56 / 56 条，无未回填；
  • 49 条找到出处、7 条标注为「多种说法并存」（降级为待核对，不进入正文）；
  • 来源以人民网党史频道、新华网、国防部网、光明网、湖北省政府网、中国社会科学院近代史所为主；
  • 团队抽查了 3 条最关键引文（毛泽东「民族革命典型」、「谢晋元命令各连清点人数造好名册」、「10 月 31 日凌晨撤入租界」），逐字比对原文无误；

插拔机制：史料卡是纯数据（sources.ts + 自动生成的 sources.auto.ts）。以后补文献只需在注册表填 excerpt（原句）与 locator（章节/页码）、把状态改成 verified、再把卡片 id 加进目标场景，场景页脚、史料库分组与「用于几个场景」全部自动更新，不需要改任何组件代码。开发环境启动时自动校验：已核对卡缺定位、场景引用了不存在的卡、引用了未核实的卡，都会在控制台直接报错。详见《史料卡模板与接入说明》。

游戏内「史料库」按文献分组，逐条列出原句、页码、作者、出版社、年份与状态；场景页脚最多显示 4 张，其余收进「另有 N 条史料」。

六、应用与传播价值

  1. 课堂可用：单周目 2—3 小时，可拆成 4—6 个课时段，每段对应一卷；每个抉择点都能引出一张史料卡。
  2. 展馆可用：纯静态站点，可离线部署在触摸屏或展厅电脑；人物志与「后来」可作独立展项。
  3. 公共记忆：把「还有一百多个名字没有人知道」做成可传播的句子，为后续名字征集留出入口。
  4. 可扩展：叙事数据与渲染分离，增加一章只需新增数据文件；图片、史料卡都是可插拔注册表。

七、AI 使用情况（详见《AI 工具使用情况说明》）

本作品在以下环节使用生成式 AI：

  • 背景图与插画：本地部署 SDXL base 1.0（fp16）+ SDXL-Lightning 4-step LoRA，逐张记录 prompt/seed/尺寸/耗时，VLM 质检（入屏 158 条逐张）+ 人工抽查，不合格重生成；
  • 文本生产：AI 辅助的分区写作与双轨审计管线（详见创新五），所有段落经史实与文学两道人工把关，真实人物不虚构台词，未核对史实不进正文；
  • 交互与结局画面：点击粒子、五种天气转场、九段 Canvas 收束动画为 AI 辅助实现，运动参数与配色由团队按叙事节奏逐项调校；
  • 真 3D 切片：四个 three.js 程序化场景（仓库内景/楼顶/桥/1947 厢房）为 AI 辅助实现，几何与光照由团队按史料照片尺度校核；
  • 音效生成：本地部署 Stable Audio Open Small（497M）生成 28 条环境音与动作音（4.88 MB），逐条记录 prompt/seed/采样率/峰值显存；EQ、响度、循环点与重采样为经典 DSP 处理，不用第二个模型；
  • 代码辅助：AI 辅助实现与测试脚本。

需要如实说明的一点：三个合成结局（约 3,100 汉字）与交互/终极画面、真 3D、音效层都是在双轨审计冻结之后新增的，没有经过独立审计员的第二轮逐段评分。它们沿用同一批已核史料卡（史料卡 id 见 docs/audit/2026-10-21-ending-expansion-note.md），并做了人工自查：真实人物零台词、无伤亡数字、第三人称、无套话清单命中；但「未经独立审计」这一点不隐瞒。

AI 不作为独立评分依据；史实认定、叙事结构、机制设计、质量标准与最终取舍由团队确定。所有 AI 生成内容均经过人工筛选、修改与整合。
