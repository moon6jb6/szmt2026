# 史料收集字典（交给另一个 AI 的作业本）

> 用途：书找不到，就把「需要什么信息」拆成 56 个编号槽位，交给收集用的 AI 去公开来源里查。
> 查回来按统一 JSON 回填，我用脚本直接并入项目，游戏里立刻能用。
>
> 配套文件：
> - [史料收集模板.json](./史料收集模板.json) —— 机器可读的 56 个槽位（把这个直接给 AI）
> - `tools/import-collected-sources.mjs` —— 回填 JSON 自动并入 `src/game/content/sources.auto.ts`

---

## 一、怎么用（三步）

1. **你把这一节 + `史料收集模板.json` 复制给另一个 AI**（文末有现成的 Prompt）。
2. 它按槽位逐条查，输出一个回填 JSON（格式见第三节）。
3. 你把回填 JSON 存成 `docs/deliverables/史料收集回填.json`，告诉我，我跑脚本并入项目。

---

## 二、给收集 AI 的规则（复制时一起带上）

**来源优先级（从高到低）**
1. 官方档案、博物馆/纪念馆官网与展陈
2. 中央与地方主流媒体：新华社、人民日报、光明日报、央视、地方党报
3. 学术专著与期刊：正规出版社、社科文献、学报
4. 当事人回忆、口述史、日记（必须注明版本）

**禁止作为最终出处**
- 百科类聚合条目（百度百科、维基等，只能当线索）
- 自媒体、公众号、短视频文案、论坛帖子
- AI 生成的总结或转述
- 影视剧情、小说、演义

**硬性要求**
- 每条必须能定位：**URL** 或 **书名 + 页码/章节**，两者都没有 = 未找到
- 原文摘句必须**逐字**，删节用「……」，不允许意译后加引号
- 同一事实说法不一 → `status: "ambiguous"`，并在 `quote` 里并列各版本
- 找不到 → `status: "not_found"`，在 `note` 写清查了哪些来源、为什么没有
- **不允许编造**：页码、书名、作者、年份、数字，一个都不许猜
- 数字类必须给出统计口径（谁统计的、统计范围）

---

## 三、输出格式（回填 JSON）

```json
{
  "filled": [
    {
      "slot_id": "B-05",
      "status": "found",
      "fact": "1937 年 10 月 28 日清晨，四行仓库楼顶升起一面旗。",
      "quote": "（逐字原句，找不到原句留空字符串）",
      "source": {
        "type": "book",
        "work": "八百壮士：中国孤军营上海抗战纪实",
        "author": "陈立人",
        "publisher": "团结出版社",
        "year": 2024,
        "url": "",
        "locator": "第 3 章《血醒租借地》，p.58"
      },
      "confidence": "high",
      "note": ""
    }
  ]
}
```

字段说明：

| 字段 | 必填 | 说明 |
|---|---|---|
| slot_id | ✅ | 必须是模板里的编号，如 `B-05` |
| status | ✅ | `found` / `not_found` / `ambiguous` |
| fact | found/ambiguous 必填 | 一句话事实，可直接写进游戏正文 |
| quote | needQuote=true 时必填 | 逐字原句 |
| source | found/ambiguous 必填 | 见下 |
| source.type | ✅ | `book` / `news` / `archive` / `museum` / `interview` |
| source.work | ✅ | 书名 / 文章标题 / 档案名 |
| source.author | 建议 | 作者 / 编者 / 发布机构 |
| source.publisher | 建议 | 出版社 / 媒体 / 馆藏机构 |
| source.year | 建议 | 出版年 / 发表年 |
| source.url | 网络来源必填 | 可点击链接 |
| source.locator | 书籍必填 | 页码 / 章节 / 段落 / 版次 |
| confidence | ✅ | `high` / `medium` / `low` |
| note | 可选 | 存疑点、版本差异 |

## 五、可直接复制的 Prompt

```text
你是史料收集员。任务：按我给的《史料收集字典》逐条收集信息，输出回填 JSON。

【项目背景】我在做一部关于 1937 年四行仓库保卫战的交互叙事作品，需要可核实的史实与可引原句。

【规则】
1. 来源优先级：官方档案/纪念馆 > 新华社/人民日报/光明日报/央视/地方党报 > 正规出版社学术专著 > 当事人回忆与口述史。
2. 禁止作为最终出处：百科类聚合条目、自媒体、公众号、论坛、AI 转述、影视剧情。
3. 每条必须能定位：URL，或书名+页码/章节。都没有就算 not_found。
4. 原句必须逐字；删节用「……」；不许意译后加引号。
5. 说法不一 → status 填 ambiguous，quote 里并列各版本。
6. 找不到 → status 填 not_found，note 写清查了哪些来源、为什么没有。
7. 绝对不许编造页码、书名、作者、年份、数字。

【输出】只输出一个 JSON 对象：
{
  "filled": [
    { "slot_id": "...", "status": "found|not_found|ambiguous", "fact": "...", "quote": "...",
      "source": { "type": "book|news|archive|museum|interview", "work": "...", "author": "...",
                  "publisher": "...", "year": 0, "url": "...", "locator": "..." },
      "confidence": "high|medium|low", "note": "" }
  ]
}

【模板】见随附《史料收集模板.json》的 slots 数组，共 56 条。先做 P0 的 16 条，再做 P1，最后 P2。
每条都要输出，不许省略 not_found 的条目。
```

## 六、收回来之后

1. 把 AI 输出的 JSON 存为 `docs/deliverables/史料收集回填.json`。
2. 我跑：
   ```bash
   node tools/import-collected-sources.mjs
   ```
   脚本会逐条校验（槽位号存在、found 必须有出处、needQuote 必须有原句、不许空定位），
   生成 `src/game/content/sources.auto.ts`，并写一份 `史料回填报告.md`。
3. 游戏自动多出这些史料卡；「史料库」按文献分组；场景页脚自动挂上。
4. 我会人工抽查 2—3 条最关键的（D-01、C-01、B-05），确认没有问题再上线。

先只做 **16 条 P0**，就足够把游戏从「新闻级叙述」提升到「可引细节」：
