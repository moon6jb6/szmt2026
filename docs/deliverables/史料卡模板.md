## 一、一张卡长什么样

```ts
{
  id: 's-baibai',
  type: 'book',                 // book | news | archive | museum | interview
  status: 'needed',             // verified | pending | needed
  work: '八百壮士：中国孤军营上海抗战纪实',   // 所属文献标题，史料库按它分组
  author: '陈立人',
  publisher: '团结出版社',
  year: 2024,
  edition: 'ISBN 9787802149298',
  claim: '四行仓库守军编成、五夜战况、租界缴械与孤军营始末。',  // 这条依据支持什么
  excerpt: '……',              // verified 必填：可直接引用的原句
  locator: '第 2 章《孤堡》，p.45',  // verified 必填：页码/章节；needed 写成「待补：…」
  note: '微信读书可搜到，优先补第 2 章',    // 内部备注，玩家也能看到
  scenes: ['night2', 'night3'], // 用在哪些场景；needed 阶段可以为空
  tags: ['四行仓库', '守军'],     // 检索标签，最多显示 3 个
}
```

## 二、三种状态

| 状态 | 含义 | 能否进正文 | UI 表现 |
|---|---|---|---|
| `verified` | 已拿到原文并核对页码 | ✅ 可以 | 页脚出现卡片；点开显示「原句 + 页码」 |
| `pending` | 有出处但原文/页码没核 | ⚠️ 只可概述 | 点开显示「待核对」，正文不应引用 |
| `needed` | 文献还没到手 | ❌ 不可以 | 只出现在「待接入文献」区，写明缺哪章 |

**自检规则（开发环境启动时自动跑）：**
- `verified` 卡缺 `excerpt` 或 `locator` → 控制台报错；
- `needed` 卡的 `locator` 不以「待补」开头 → 报错；
- 场景引用了不存在的卡、或引用了非 `verified` 卡 → 报错；
- 卡片 `scenes` 里写了不存在的场景 id → 报错。

控制台输出示例：
```
[史料卡校验] 通过：14 条（已核对 8 / 待接入 6），覆盖 8 个场景
```

## 三、接入一本书的完整流程（4 步）

以《八百壮士》第 2 章为例：

**第 1 步：改卡**
把 `sources.ts` 里 `s-baibai` 的：
```ts
status: 'needed',
locator: '待补：第 2 章《孤堡》…',
```
改成：
```ts
status: 'verified',
excerpt: '（从书里抄的原句）',
locator: '第 2 章《孤堡》，p.45',
```

**第 2 步：挂到场景**
在 `chapter1.ts` 对应场景加 id：
```ts
const NIGHT2: Scene = {
  ...
  sources: ['s-tongcheng', 's-baibai'],   // 加在这里
}
```

**第 3 步：跑起来看**
- 场景页脚自动多一张卡；
- 点开就是「原句 + 章页 + 书名/作者/出版社/年份」；
- 「史料库」页自动从「待接入」挪到「已核对」。

**第 4 步：跑一次回归**
```bash
npm run build
node tools/ending-test.mjs http://127.0.0.1:4173/
```
确认 6 个结局仍然全通、控制台无报错。

## 四、写作规范（避免踩坑）

1. **一条卡只支持一个陈述**。一句话说不清就拆两张。
2. **原句不改字**。要删节用「……」；不要意译。
3. **页码必须是真的**。电子书用「章节 + 位置」也行，但要能在平台上复现。
4. **真实人物不虚构台词**。卡里的 `excerpt` 只能是文献原文，不能是团队写的。
5. **拿不到就保持 `needed`**。宁可空着，不要用「据说」「有记载」含糊带过。
6. **同一本书的卡共用 `work`**，史料库会自动分组。
