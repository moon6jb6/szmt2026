﻿# AI 工具使用情况说明

参赛团队参考模板对应材料。按《参赛作品材料提交规范》第九部分要求填写。

一、总体说明

本作品在创作过程中使用了生成式人工智能工具，主要用于视觉素材生成、文本生产与审计、代码辅助。作品的核心创意、叙事结构、机制设计、史料选择与事实核对、质量标准与最终取舍由团队成员确定。AI 生成内容均经过可复核的筛选、修改与审计，不存在「一键生成整件作品」的情况。

本版特别把 AI 的使用过程做成了可审计的管线：分区写作 → 双轨审计（史实/文学）→ 逐条修改 → 复审计，全过程报告与可复现脚本随作品提交（docs/audit/）。

三、代表性环节一：场景插画生成与逐张质检

AI 输入

  • 统一视觉圣经（色板、镜头语言、禁止项）与 500 条图片总谱（docs/art/image-manifest.json）：每条含场景 id、prompt、negative、seed、尺寸、用途；
  • 提示词示例（四行仓库内景）：cinematic film still, 1937 China, muted desaturated warm sepia palette, volumetric haze, painterly realism, empty concrete warehouse interior, burlap sandbags, dust in light shaft, no people, no text；
  • 参数：本地 SDXL + Lightning 4 步、固定 seed、CPU offload（8GB 显存）、逐张记录参数与耗时。

AI 输出

场景/关键瞬间/文物/人物剪影/结局插画候选图。

团队后续处理

  1. VLM 逐张质检：四维打分（prompt 符合度 / 时代准确性 / 画面瑕疵 / 危险元素），输出 pass / retry / reject；retry 换 seed 重生成；
  2. 人工抽查：每 50 张抽 10 张，重点看「有没有叙事信息」（具体物、一道光、人的缺席），以及是否出现清晰人脸、文字、现代物、旗帜图案错误；
  3. 不合格图归档到 tools/imagegen/out-art/rejected/，并记录原因；
  4. 通过质检的图按 docs/art/scene-map.json 与场景 id 映射挂载，不承担史实表述功能，不出现具体人物面孔。

最终成果中的使用

场景页横幅插画、人物志与「后来」读者页配图。图片不作为史料证据。

四、代表性环节二：分区写作 + 双轨审计（113,138 字）

AI 输入

  • 已确定的故事大纲、人物设定、叙事圣经与硬性约束（不虚构真实人物台词、不写伤亡数字、第三人称限知、禁用套话清单、每段必须有具体物与动作）；
  • 76 张史料卡（已核 63 张 / 待核 7 张 / 待接入 6 张）与逐场挂卡要求；
  • 分区任务：序卷+卷一、卷二（四行五夜）、卷三+卷四（孤军营/记忆线）、支线人物志。

AI 输出

各卷场景数据（TypeScript 数据文件：场景、段落、抉择、结果、史料卡引用）。

团队后续处理

  1. 史实审计：逐场景对照史料卡，检查真实人物台词、时间线、挂源覆盖、红线（暴行细节、伤亡数字、未核史实）；P0 必须为 0；
  2. 文学审计：逐单元五维评分（具体性/情感真实/语言干净/结构功能/意象系统），均分 ≥4.0 且无单项 <3；AI 味、套话、解释性旁白、三连排比零容忍；
  3. 迭代修改：每轮审计出编号清单，作者逐条修改后复审，最多 3 轮；
  4. 集成校验：构建、场景链可达性、史料卡引用存在性、严格字数统计全部用脚本复现。

最终成果中的使用

游戏正文与附加读者页。审计结论：文学 P0 = 0、不合格 0 / 146 经审单元（3 个合成结局已补独立审计：史实 P0=0、文学均分 4.35）、加权均分 4.59；史实 P0 = 0；严格正文 113,048 字（tools/count-words-strict.mjs 可复现）。

补充说明（如实披露）：六个主结局经过完整双轨审计；新增的三个合成结局（档案 / 遗物 / 口耳，约 3,141 字）已在 2026-10-22 补做独立双轨审计——史实 P0 4→0、文学 3.99→4.35（报告：docs/audit/2026-10-22-composite-fact.md / -literary.md）。点击/结局画面交互、5 个真 3D 场景（含 Blender 建模的仓库西墙）与 28 条音效不承担史实表述，做人工验收与性能测试；覆盖边界见 docs/audit/2026-10-22-post-audit-addendum.md。

五、代表性环节三：环境音生成（28 条）

AI 输入

  • 每个音效的用途与质感描述（克制、具体、不煽情），如「记忆载体 名册 点击：厚册页翻开合上，闷、沉、有分量」；
  • 固定 seed、8—10 秒片段、循环类 22 秒并要求首尾可无缝衔接。

AI 输出

  • Stable Audio Open Small（497M）本地生成的原始 wav（44.1 kHz）；
  • 每条记录 prompt / seed / steps / 耗时 / 峰值显存（2.8—3.3 GiB，manifest 峰值 3,364 MiB）/ 许可。

团队后续处理

  1. 用经典 DSP（非第二个模型）做 EQ、响度归一、循环点交叉淡化、重采样到 48 kHz、导出 OGG；
  2. 逐条检查波形与频谱（tools/audio/inspect_audio.py），循环接缝做跳变检测；
  3. 接入 Web Audio：默认静音、用户手势解锁、场景/天气映射、同一时刻最多一条环境声 + 一条结局低音、页面隐藏即 suspend；
  4. 全部参数写入 docs/audio/audio-manifest.json，可复现。

最终成果中的使用

游戏内环境音与交互音效（28 条 / 4.88 MB）。不承担史实表述；音量与开关由用户控制。

六、代表性环节四：代码辅助

AI 输入

  • 数据模型与状态机设计（由团队确定）
  • 组件职责划分与约束（无后端、无外部字体、首屏体积目标）

AI 输出

TypeScript 组件与样式初稿。

团队后续处理

  1. 逐文件审查类型与边界条件；
  2. 编写自动化测试，验证 9 个结局全部可达（9/9 通过）；
  3. 性能与可访问性检查：键盘操作、减少动效、移动端布局；
  4. 修正类型错误与运行时错误，直到构建零报错。

七、版权、数据与合规

  • 生成图仅用于本作品的场景背景，不包含真实人物肖像，不复制现有摄影作品。
  • 文字内容不直接引用受版权保护的原文；史料事实以概述方式呈现并注明出处。
  • 未使用任何未公开的个人信息、声音或肖像数据。
  • AI 生成内容已在作品材料中如实披露，未隐瞒使用情况。

八、AI 不参与的部分（团队原创贡献）

  • 选题与切入角度（「把名字留下来」）
  • 记忆载体机制与九个结局的结构
  • 史料筛选标准与「史实层 / 表现层」分离原则
  • 全部史实表述的核对与出处标注
  • 最终文案、视觉规范、交互流程与测试
